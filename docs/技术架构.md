# 海信 AI 招聘智能体 · 技术架构

## 一、系统定位

海信容声（广东）冰箱的 AI 招聘智能体，把「JD 发布 → 简历筛选 → 风险识别 → 面试辅助 → 人才评价」全流程自动化。核心不是替 HR 做最终录用决定，而是把主观、慢、不可复现的人工筛简历，变成确定性、可解释、可复现的评分，让 HR 拿到「为什么是这几个人」的可信答案。

## 二、三层架构

```
┌───────────────────────────────────────────────┐
│ 展示层                                        │

└────────────────────┬──────────────────────────┘
                     │ HTTP + WebSocket（CORS）
┌────────────────────▼──────────────────────────┐
│ 算法层（FastAPI，端口 8000）                   │
│  确定性评分引擎 / LLM 简历解析 / 风险识别       │
│  面试辅助(面试题+纪要+评分) / 人才评价(入库+递补)│

└───────────────────────────────────────────────┘
```

## 三、核心模块

### 1. 确定性评分引擎（`scoring.py` + `matcher_v2.py`）

- **三态评分**：每个维度返回「满足 / 不满足 / 未知」，区分「字段缺失」和「字段不满足」，不误杀信息缺失的候选人。
- **学历打分化**：学历是打分维度（博士>硕士>本科>大专>中专>高中>初中），大专 + 对口经验可补偿加分，不做一票否决。
- **淘汰信号分级**：重信号（求职意向不符/薪资超/频繁跳槽/无制造业经验）扣分或一票否决；轻信号（到岗/通勤/薪资略高）待确认。
- **双向锚定**：每个匹配维度回溯到简历真实字段或可观测代理，简历抽不到的维度移给面试/背调。
- **权重可配置**：权重存在飞书「权重配置表」，HR 实时调整，不改代码。

### 2. LLM 简历解析（`llm_resume_parser.py`）

- 用 DeepSeek-chat 把非标简历（口语化/字段缺失）解析成结构化字段，对齐飞书简历库。
- 真实简历导入闭环：粘贴/上传简历 → LLM 解析 → 写飞书简历库 → 自动评分 → 前端刷新可见。

### 3. 风险识别（`risk_filter.py`）

- 工作经历断层、频繁跳槽、证书过期、简历造假、核心技能真实性待核验。
- 每条风险带核验动作（如「请核验证书原件与有效期」），不是只标风险。

### 4. 面试辅助（`interview.py` + 视频面试）

- 结构化面试题：按岗位族生成题库 + 简历短板/风险点定向追问。
- 面试纪要：线上面试对话 LLM 自动梳理纪要 + 评分评级。
- 视频面试：腾讯云 TRTC 实时音视频房间 + ASR 语音转写 + COS 录制落盘，带说话人分离的权威纪要。

### 5. 人才评价汇总（模块 4）

- 人才来源优先级：先内部人才库 → 历史候选人复用 → 外招兜底。
- 候选人对比：按岗位取 top 候选人，对比匹配分/风险/面试重点。
- 入库 + offer 递补：合格候选人自动入库，offer 放弃时按优先级递补。

## 四、技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.14 + FastAPI + uvicorn + pydantic |
| AI | DeepSeek-chat（V3.2，简历解析 + 面试纪要） |
| 数据 | 飞书多维表格（bitable，9 张表） |

## 五、数据模型（飞书 9 张表）

招聘需求表、简历库、权重配置表、评分结果表、面试采集表、面试记录表、招聘进度表、内部人才库、历史候选人库。

## 六、关键设计原则

1. **确定性优先**：同一份简历任何机器跑出同一分数，LLM 只在语义判断介入。
2. **可解释**：每个分数追到规则行 + 简历原文证据，每条风险带核验动作。
3. **合规**：年龄/性别/婚育等不作自动淘汰依据，学历不机械一票否决。
4. **真实可落地**：真实简历投进来能发生真实筛选，不是只看预置 mock 数据。
