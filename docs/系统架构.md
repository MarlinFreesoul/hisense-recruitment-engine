# 系统架构

## 一、三层架构

```
┌──────────────────────────────────────────────────────────┐
│ 飞书（前端 / 数据层）                                      │
│  多维表格：岗位库·简历库·评分库·人才库                      │
│  机器人 / 应用：HR 交互入口                                │
└──────────────────────────┬───────────────────────────────┘
                           │ REST API · Webhook（飞书开放平台）
┌──────────────────────────▼───────────────────────────────┐
│ 确定性代码（算法层 · 可 clone 部署到任意机器）               │
│  resume_parser  简历解析 → JSON                            │
│  jd_gen         JD 生成（模板+参数）                        │
│  scoring        打分（评分函数，可复现）                    │
│  risk_filter    风险过滤                                   │
│  pipeline       漏斗编排                                    │
└──────────────────────────┬───────────────────────────────┘
                           │ MCP（PromptX 作为 MCP server）
┌──────────────────────────▼───────────────────────────────┐
│ PromptX 角色（业务智能层）                                  │
│  data · screening · risk · interview · talent             │
│  hr-expert（定标准/权重）· architect（节点契约）            │
└──────────────────────────────────────────────────────────┘
```

## 二、业务流转（招聘漏斗）

```
[用人部门] 需求 → ①JD生成 → ②简历池(1000份) → ③简历结构化[data]
   → ④简历筛选[screening] 硬条件+软条件=0-100分
   → ⑤风险识别[risk] → ⑥推送用人部门(匹配+风险)
   → ⑦电话初面[HR] → ⑧面试辅助[interview] 题库+纪要+评价
   → ⑨人才评价[talent] 对比表+入库 → ⑩选人决策/备选推送
```

## 三、打分逻辑（确定性、可复现）

**硬条件**（布尔，一票否决）：

| 维度 | 简历字段 | 判法 |
|---|---|---|
| 年龄 | 基本信息.age | 规则（区间） |
| 学历 | 教育.degree | 规则（层级比较） |
| 到岗 | 期望.到岗时间 | 规则 |
| 倒班 | 自我评价.关键词 | 关键词 |

**软条件**（评分函数 × 权重）：

| 维度 | 评分函数 | 权重 |
|---|---|---|
| 稳定性 | 最近一段工作 ≥2年=10 / 1-2年=7 / 0.5-1年=4 / <0.5年=2 | 0.30 |
| 软实力 | 自我评价关键词命中 ×2，上限10 | 0.30 |
| 经验 | 年限 ≥3=10 / 1-3=7 / <1=4，对口+1 | 0.20 |
| 技能 | required命中率×6 + preferred命中 + 证书，上限10 | 0.20 |

**总分 = Σ(维度分 × 权重) × 10 → 0-100**，评级：≥90 A / ≥75 B / ≥60 C / <60 不推荐。

## 四、双向锚定原则

每个匹配维度必须回溯到简历真实字段或可观测代理；简历里抽不到的维度（动机/健康/技能真实性），**移出快速筛选**，交给面试 STAR / 背调 / 体检。

## 五、数据契约

- `job_families_v2.json` 是**单一数据源**，含两个视图：
  - 匹配视图（`hard_filters`/`soft_scores`/`deferred_checks`/`skill_model`）→ `compute_match` 用
  - 展示视图（JD 四字段）→ `generate_jd` 渲染用
- 简历结构化字段与 JD 字段同构（命名统一），是 screening/risk 的输入。
