# 海信 AI 招聘智能体 · 产品需求文档（PRD）

> 版本 v2.0 · 2026-08-15 · 覆盖：打分维度、简历评价、面试评价、岗位匹配度评价

## 一、产品概述

### 1.1 目标

海信容声（广东）冰箱的 AI 招聘智能体，从「JD 发布 → 简历筛选 → 风险识别 → 面试辅助 → 人才评价」全流程中，用**确定性规则 + 可解释评分**替代人工筛选，让 HR 拿到「为什么是这几个人」的可信答案。

### 1.2 核心原则

1. **确定性优先**：同一份简历在任何机器跑出同一分数，每个分数追得到规则行，LLM 仅在语义判断（专业对口）介入。
2. **三态评分**：「没写」≠「不满足」——字段缺失标「未知」剔除不扣分，字段写了但不达标才扣分。
3. **可解释**：每个维度得分挂证据，每条风险带核验动作，每个结论可回溯到简历原文。
4. **权重可配置**：权重存在飞书「权重配置表」，HR 可实时调整，不需要改代码。

### 1.3 数据流

```
飞书多维表格（岗位/简历/权重/评分结果）
   ↓ 后端实时读取
评分引擎（硬条件 + 软条件 + 风险）
   ↓ 产出结构化评分
demo / 前端（展示可解释评分 + 面试题 + 表单采集）
```

## 二、打分维度体系

### 2.0 记分卡：先定标准再找人

评分维度的起点不是「要什么能力」，而是「岗位做成了是什么样」。每个岗位族先定义**记分卡三要素**，再据此派生评分维度：

| 要素 | 含义 | 示例（装配工） |
|---|---|---|
| 成功产出 | 岗位做好了的结果画像 | 一个月稳定到岗、三个月不流失、日产能达标 |
| 使命 | 岗位存在的意义 | 保障冰箱装配线稳定产出 |
| 能力要求 | 达成产出所需的能力 | 装配技能、倒班接受度、稳定性 |

> 原则：**记分卡先于寻访**——先写成功画像，再筛选，拒绝「凭直觉光环」的巫毒招聘。

### 2.1 两层结构

| 层 | 作用 | 判定方式 |
|---|---|---|
| **硬条件**（门槛） | 一票否决，不满足直接淘汰 | 布尔规则 |
| **软条件**（加权） | 计算匹配度 0-100 | 评分函数 × 权重 |

### 2.2 硬条件（每岗位族不同）

| 岗位族 | 硬条件 |
|---|---|
| 一线生产 | 学历不限、倒班接受、到岗时间 |
| 现场管理/管培 | 本科、理工科专业 |
| 工艺/IE/设备 | 本科、机械/电气/制冷等专业 |
| 质量/测试 | 本科（工程师）/ 不限（质检） |
| 采购/物流 | 本科、采购/物流/供应链专业 |
| 研发/工程 | 本科、计算机/电子/安全专业 |

### 2.3 软条件维度与权重（权重可在飞书调）

| 岗位族 | 维度及权重 |
|---|---|
| 一线生产 | 稳定性 30 · 软实力 30 · 经验 20 · 技能 20 |
| 现场管理/管培 | 软实力 40 · 专业对口 25 · 经验 20 · 技能 15 |
| 工艺/IE/设备 | 技能 30 · 专业对口 30 · 经验 20 · 软实力 20 |
| 质量/测试 | 技能 30 · 专业对口 25 · 经验 25 · 软实力 20 |
| 采购/物流 | 专业对口 25 · 技能 25 · 经验 25 · 软实力 25 |
| 研发/工程 | 技能 35 · 专业对口 25 · 经验 25 · 软实力 15 |

### 2.4 三态：满足 / 不满足 / 未知

每个维度评分返回三态之一：

| 状态 | 含义 | 对总分影响 |
|---|---|---|
| 满足 | 字段存在且达标 | 计入分子分母 |
| 不满足 | 字段存在但不达标 | 计入分母，分子计低分 |
| 未知 | 字段缺失/无法判断 | **从分母剔除**，不惩罚 |

**匹配度 = Σ(非未知维度得分×权重) / Σ(非未知维度权重) × 10**（归一化，未知维度不占分母）。

### 2.5 合规红线（劳动法合规）

以下信息**不得作为自动淘汰依据**：

- 年龄、性别、婚育状况、民族、宗教信仰、健康史
- 除非岗位有法定的客观必要性（如高空/特种作业的年龄限制）

> 涉及这些字段的评分维度，一律降级为「人工复核」，不允许机器一票否决。

## 三、简历评价

> 方法论：胜任力模型用行为事件访谈（BEI）建立，提取影响力/成就欲/团队领导/主动性等关键胜任特征，而非拍脑袋定维度。评分维度分「知识/技能/行为」三类，每个维度对应行为锚点。

### 3.1 简历结构化（LLM）

非标简历（口语化/字段缺失/格式混乱）→ LLM 提取 → 标准字段（对齐飞书简历库 17 字段：姓名/学历/专业/工作年限/技能/证书/自我评价/应聘岗位/地点/薪资/到岗…）。

### 3.2 硬条件检查（布尔）

学历是否达标、专业是否对口、倒班是否接受、到岗是否满足——任一不满足直接「不推荐」。

### 3.3 软条件评分（每维度评分函数，0-10 分）

| 维度 | 评分函数 | 证据示例 |
|---|---|---|
| 稳定性 | ≥5年=10 / 3-5年=9 / 2-3年=8 / 1.5-2年=7 / 1-1.5年=6 / 0.5-1年=4 / <0.5年=2 | 「最近一段工作 3 年，稳定」 |
| 软实力 | 命中关键词（吃苦/倒班/协作/团队/纪律/抗压/认真/责任/踏实）每个+2，上限10 | 「命中关键词：吃苦、倒班、协作、团队」 |
| 经验 | 对口：≥5年=10 / 3-5年=9 / 1-3年=7 / <1年=4；不对口各减1 | 「3 年经验，行业对口」 |
| 技能 | required命中率×8 + preferred命中+1 + 证书+1 | 「命中技能：装配；加分：钳工、电工；证书：电工证、钳工证」 |
| 专业对口 | 专业大类→岗位族命中=10，不命中=3，无法判断=未知 | 「专业『机械制造』对口」 |

### 3.4 风险识别与资质核验（对照 require.txt 模块 2）

> require.txt 原文要求：智能识别**简历造假、工作经历断层、证书过期、频繁跳槽**等风险点，对**技术岗位、职能岗位核心技能真实性**进行初步核验，输出**候选人风险评估报告**，推送给 HR 及用人部门。

**模块边界（与 scoring 同原则）**：简历里判得了的，用确定性规则直接标；简历判不了的（实操水平、是否真会），一律「标风险 + 给核验动作」，交面试 STAR / 背调，**机器不代替人工下结论**。每条风险都带 `advice`（核验动作），通过 `/interview/questions` 生成面试题、随评分结果写回飞书、推送 HR 及用人部门。

#### 3.4.1 四类风险点（确定性识别规则）

| 风险类型 | 识别规则（确定性） | 等级 | 核验动作（advice） |
|---|---|---|---|
| **简历造假** | ① 相邻工作时段重叠；② 首份工作早于毕业 >6 个月；③ 标注任职时长与时间段跨度相差 >1.5 年 | 重叠/矛盾=**高**，时长不符=**中** | 核验各段经历真实性（社保/合同/背调证明人）；学信网核学历 |
| **工作经历断层** | 解析 `period` 起止日期，相邻两段 Gap ≥3 个月（或毕业→首份工作 Gap ≥3 个月）；≥6 个月判**高** | 中 / 高 | 确认空窗期去向（求学/待业/创业），背调核实 |
| **证书过期** | 解析 `expiry`：实际日期早于今天 → **证书过期（高）**；缺日期/「未注明」→ **证书核验（中）** | 高 / 中 | 过期证书不予采信，核验最新有效证书；未注明者核原件与有效期 |
| **频繁跳槽** | 工作段数 ≥3 且平均每段 <1 年 | 中 | 确认离职原因与稳定承诺 |
| **期望错位** | 求职意向与目标岗位不一致 | 中 | 电话确认求职意向与留存意愿 |
| **短期任职** | 存在单段任职 <6 个月 | 中 | 确认离职原因与稳定承诺 |

> 说明：旧版「稳定性」弱代理（最近一段<0.5 年）已升级为上述「工作经历断层（日期区间）」+「短期任职」，不再依赖不可靠的近似。

#### 3.4.2 资质核验：核心技能真实性（技术 / 职能岗）

require.txt 点名要对**技术岗位、职能岗位**做核心技能真实性初步核验。做法是与岗位族 `skill_model.required` 交叉比对：

- 取岗位族核心技术清单（如工艺/设备：`工序优化·工艺控制·工装器具·异常改善`）；
- 若候选人**声称**某核心技能（出现在技能清单），但在**工作履历（职责/业绩）与证书中均无佐证** → 标「**核心技能真实性待核验（中）**」；
- 核验动作：面试实操或背调核验该技能真实水平。

> 边界：机器只判「有/无证据支撑」，不判「会不会」。一线生产岗以硬条件/体力为主，不做此核验（避免噪声）。技能真实性最终在面试 STAR + 背调闭环。

#### 3.4.3 风险评估报告与推送

- `risk_report` 输出：`risks[]`（类型/等级/证据/核验动作）+ `overall_level`（取最高等级）+ `deferred_to`（面试 STAR / 背调 / 体检）。
- **整体风险高** → 推荐结论降级为「待定（高风险，建议人工复核）」，不自动淘汰。
- 报告随「评分结果表」写回飞书，并推送 HR 及用人部门；风险点同时注入 `/interview/questions` 生成针对性核验问题。

> 合规护栏：风险识别仅基于工作经历、证书、技能、求职意向等岗位相关字段；不触碰婚育/民族/健康史，不以此自动否决。

## 四、面试评价

> 理论依据：结构化面试比非结构化更公平、评分者一致性更高（Chapman 2005）；结构化行为面试（STAR 追问）能减少面试官偏差。因此面试评价以**结构化**为核心，不做开放式随意提问。

### 4.1 结构化采集（H5 表单，零 LLM 对话）

核心问题 = 硬指标 + 关键软条件，**参数化生成**（证书名、岗位名可替换）：

| 问题来源 | 问题模板 | 输入类型 |
|---|---|---|
| 硬条件·倒班 | 能接受两班倒/夜班吗？ | 单选 |
| 硬条件·到岗 | 什么时候能到岗？ | 单选 |
| 风险·证书 | 你的{证书名}有效期到什么时候？ | 文本 |
| 风险·期望 | 求职意向与岗位有落差，能说说吗？ | 文本 |
| 软条件·沟通/抗压/团队 | 评价你的沟通/抗压/协作能力 | 单选 |

每个问题带三要素（对应飞书字段）：**为什么问**（核验目的）、**期望信号**（正面回答）、**风险信号**（负面回答）。

### 4.2 结构化面试题（给面试官）

按岗位族生成题库（STAR 追问），针对简历短板 + 风险点定向追问。

## 五、岗位匹配度评价

### 5.1 匹配度（0-100）

硬条件全过 + 软条件归一化加权 = 匹配度 0-100。

### 5.2 匹配度分级（对照学术标准）

| 匹配度 | 等级 | 人才分级 | 对应结论 |
|---|---|---|---|
| 81-100 | 完全匹配 | **A 级**（达成结果概率超九成） | 推荐 |
| 61-80 | 基本匹配 | **B 级** | 推荐 / 待确认 |
| 41-60 | 相当匹配 | B/C 级 | 待确认 |
| 21-40 | 不匹配 | C 级 | 不推荐 |
| 1-20 | 非常不匹配 | 不录用 | 不推荐 |

> 原则：招聘的目标是**提升 A 级命中率**，而非降低录用成本。

### 5.3 维度得分（可解释）

每个维度输出：`维度名 / 得分 / 满分 / 证据 / 扣分原因`，进度条按 `得分/满分` 渲染。

### 5.3 推荐结论（三分类）

| 结论 | 判定 |
|---|---|
| 推荐 | 硬条件通过 且 匹配度 ≥75 |
| 待确认 | 硬条件通过 但 匹配度 <75，或存在未知维度待补采 |
| 不推荐 | 硬条件不通过 |

### 5.4 结论原因（分三列）

- **推荐原因**（recommend_reasons）：满足的维度证据，如「3 年经验，行业对口」
- **待确认原因**（pending_reasons）：未知维度，如「专业未填写，待确认」
- **淘汰原因**（reject_reasons）：不满足维度，如「学历未达本科」

### 5.5 风险核验点（带动作）

每条风险输出：`风险类型 / 等级 / 证据 / 建议核验问题`。

## 六、数据来源与权重配置

| 数据 | 存储 | 说明 |
|---|---|---|
| 岗位（JD） | 飞书「招聘需求表」 | 岗位名称/描述/任职资格/需求人数 |
| 简历 | 飞书「数据表」 | 17 字段，含应聘岗位 |
| 权重 | 飞书「权重配置表」 | HR 可实时调，每一分有评分规则说明 |
| 评分结果 | 飞书「评分结果表」 | 匹配度/结论/原因/风险 |
| 面试采集 | 飞书「面试采集表」 | H5 表单回复 |

## 七、可解释性保障

1. 每个分数 → 追到评分函数规则行
2. 每个结论 → 追到维度证据（简历原文片段）
3. 每条风险 → 带核验动作（不是只标风险）
4. 权重变更 → 飞书留痕，实时生效
