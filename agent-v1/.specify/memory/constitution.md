# Project Constitution

> 项目宪法：所有规格（spec）与实现（implementation）必须遵守的最高原则。
> 本文件是 Spec Kit 的「法律」，任何 spec / plan / tasks 都要通过 Constitution Check。

## 核心原则

1. **Spec First** — 先写规格，再写代码；没有 spec 的功能不进入实现。
2. **可执行优先** — 黑客松语境下，优先产出可运行的最小原型，而非堆砌 Demo。
3. **不可变性** — 始终创建新对象，禁止原地 mutate。
4. **小文件高内聚** — 单文件 200–400 行，最多 800 行；按功能域组织，而非按类型。
5. **错误处理完备** — 所有危险操作必须 try/catch 并给出明确错误信息。
6. **输入校验** — 所有外部输入必须 schema 校验（如 zod）。
7. **可测试性** — 目标测试覆盖率 80%+，关键路径 E2E 覆盖。

## 反原则（不做）

- 不在规格未定时写具体实现
- 不硬编码密钥 / 敏感信息（一律走环境变量）
- 不为赶进度牺牲可测试性与代码质量

---

_Constitution Check：每个 spec 提交前，逐条对照上述原则。_
