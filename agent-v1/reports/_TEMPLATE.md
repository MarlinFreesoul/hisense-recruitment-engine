# 报告模板 · 四要素标准

> 每份 `reports/` 下的报告必须遵循此模板，清晰呈现四要素。文件名 = `R.T-主题.md`。

---

## 报告头部（必填）

```markdown
# R.T 主题

> 一句话总结：<主题 + 本轮最关键的一个动作>
> 所属轮次：R<T> ｜ 来源：<Metaso / Exa / 双引擎 / 现场>
```

## 四要素

### ① 信源与信源评分

| 等级 | 判定 |
|------|------|
| 5分 | 官网 / 政府官网 |
| 4分 | 大牌官方媒体 / 学术研究 |
| 3分 | 厂商官方文档 / 公众号 |
| 2分 | 社交 / 招聘平台 / 内容营销 |

每个信源列明 **URL + 评分 + 理由**；结论按评分加权（高可信优先）。

### ② 权重与矩阵逻辑

明确评分维度、各维度权重（合计 100%）、各方案打分（1-10），给出加权总分。
权重必须与场景绑定（例：黑客松下「时间到 Demo」权重最高）。

### ③ 对抗性辩证矩阵

对每个关键结论，写出 **正方（For）/ 反方（Against）/ 化解（Resolution）**：

| 命题 | 正方 | 反方 | 化解 |
|------|------|------|------|
| ... | ... | ... | ... |

原则：主动替自己的结论找反例，而非只列支持证据。

### ④ 接入 Promptx 后的角色分工

| 角色 | handle | 负责模块 | 边界 |
|------|--------|---------|------|
| 女娲 | nuwa | 角色设计与世界架构 | 不替角色执行职责 |
| Spec Kit Lite 专家 | spec-kit-lite-expert | 方法论 + 地图板溯源 | 不做业务实现 |
| ... | ... | ... | ... |
